# Testing Artifacts Management

This document outlines the strategy for managing test-generated artifacts in this repository. A consistent approach to handling these files is crucial for maintaining a clean version control history, reducing repository size, and ensuring a smooth and efficient CI/CD pipeline.

## What Are Test Artifacts?

Test artifacts are files generated during the execution of the test suite. They include, but are not limited to:

- **Test Reports**: HTML, XML, or JSON reports detailing test results (e.g., `test-results/`).
- **Screenshots and Videos**: Captured by Playwright during E2E and visual regression tests, especially on failure.
- **Coverage Reports**: HTML and JSON files generated by Jest to show code coverage (`coverage/`).
- **Log Files**: Temporary logs created during test runs.

## Why Exclude Artifacts from Version Control?

Test artifacts should **never** be committed to the Git repository for several reasons:

- **Repository Bloat**: Artifacts like screenshots and videos can be large and will significantly increase the size of the repository over time.
- **Noise**: Committing generated files adds noise to the commit history, making it harder to track meaningful code changes.
- **Merge Conflicts**: Binary files like images are difficult to merge and can frequently cause conflicts.
- **Redundancy**: Artifacts are specific to a single test run and are quickly outdated. They should be generated on-demand in the CI environment.

## Artifact Directory Structure

All test-related artifacts are standardized to be output into the following top-level directories:

- `/test-results/`: Contains all reports from Playwright and Jest, including JUnit XML, JSON outputs, and the Playwright HTML report.
- `/coverage/`: Contains the code coverage report generated by Jest.

These directories are explicitly listed in the `.gitignore` file to prevent them from being accidentally committed.

## Accessing Artifacts from CI

When a test run fails in the CI/CD pipeline (GitHub Actions), the test artifacts are automatically uploaded and attached to the workflow run. This allows you to download, inspect, and debug the test results without needing to run the tests locally.

To access the artifacts:

1.  Navigate to the **Actions** tab in the GitHub repository.
2.  Find the failed workflow run for your branch or pull request.
3.  On the summary page for the run, you will find an **Artifacts** section.
4.  Download the `test-results-<ID>` zip file, which contains all the reports and logs from the failed run.

## Local Cleanup

To remove all generated test artifacts from your local development environment, you can run the `clean` script defined in `package.json`:

```bash
npm run clean
```

This command will delete the `/test-results/` and `/coverage/` directories, as well as other build-related outputs, restoring your workspace to a clean state.
