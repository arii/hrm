# Testing Guidelines

This document outlines the standards for testing infrastructure, artifact management, and best practices for writing tests in the HRM project.

## Guiding Principles

- **Reliability**: Tests must be reliable and produce consistent results. Flaky tests erode confidence and should be fixed or removed.
- **Clarity**: Tests should be easy to understand. The name of the test and its structure should clearly communicate its intent.
- **Isolation**: Tests should be isolated from one another. The failure of one test should not impact the outcome of another.

## Test Artifact Management

Test artifacts are any files generated during a test run. This includes, but is not limited to:

-   Screenshots from visual regression tests
-   Test reports (e.g., HTML, JSON)
-   Logs generated by the test runner
-   Coverage reports

**Rule**: Under no circumstances should test artifacts be committed to the git repository. These files are transient and specific to a particular test run.

## `.gitignore` Configuration

To prevent accidental committing of test artifacts, the `.gitignore` file must be kept up-to-date with patterns that cover all generated test outputs.

### Standard `.gitignore` Patterns for Testing

```
# Test Artifacts
/playwright-report/
/test-results/
/playwright/.cache/

# Coverage
/coverage/
.nycrc

# Logs
*.log
npm-debug.log*
yarn-debug.log*
yarn-error.log*
```

It is the responsibility of every developer to ensure that if a new testing tool or process is introduced, the corresponding output directories are added to `.gitignore`.

## Use Configurable Paths for Test Outputs

Hardcoded absolute paths in test scripts are a major source of brittleness and are strictly forbidden. They make the test suite difficult to run on different machines and in CI/CD environments.

### Incorrect Pattern (What to Avoid)

```typescript
// Do not use absolute paths.
const outputPath = '/Users/arii/hrm/test-screenshots';
```

### Correct Pattern

All paths for test inputs and outputs should be relative to the project root or configured via environment variables.

```typescript
// Good: Relative path from project root.
const outputPath = './test-results/screenshots';

// Better: Using an environment variable for flexibility.
const outputPath = process.env.SCREENSHOT_PATH || './test-results/screenshots';
```

This ensures that the test suite is portable and can be easily configured to run in any environment.
